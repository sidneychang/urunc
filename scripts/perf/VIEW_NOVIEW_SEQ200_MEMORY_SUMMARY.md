# view / no-view 顺序启动 200 容器内存与存储变化记录

本文整理一次 `N=200` 的 `view` / `no-view` 对照实验结果，重点展示：

- 启动前基线 `before_sequential_200`
- 启动过程粗粒度采样点：`50 / 100 / 150 / 200`
- 启动完成后的稳定采样点：`after_start_200_of_200_settle_{5,20,60}s`

所有表格中的数值单位均为 **MiB**。

- 表内格式：`当前值 (相对 before 的变化量)`
- `MemAvailable` 变化为负，表示系统可用内存下降
- `thin_data` / `thin_meta` / `run_containerd` 为存储相关指标

## 实验口径

- `view`: `make install`
- `no-view`: `cp /usr/local/bin/bak/* /usr/local/bin/`
- 运行方式：顺序启动 `200` 个容器
- 采样间隔：每 `10` 个容器采样一次，这里只摘出 `50` 粒度
- 稳定点：启动 200 个容器后，再等待 `5s / 20s / 60s`

## 快速结论

- 从 **系统总内存变化** 看，使用 `MemAvailable` 最直观：
  - `view` 在 `settle_60s` 时相对基线下降 **22725.1 MiB**
  - `no-view` 在 `settle_60s` 时相对基线下降 **24515.1 MiB**
  - 即 **no-view 比 view 多消耗约 1790.0 MiB 的系统可用内存**
- 从 **Shmem** 看，差异非常明显：
  - `view` 在 `settle_60s` 时仅增加 **12.5 MiB**
  - `no-view` 在 `settle_60s` 时增加 **1403.9 MiB**
- 从 **存储** 看，稳定点两者几乎一致：
  - `thin_data` 都收敛到 **2474.5 MiB**
  - `thin_meta` 都收敛到 **2511.0 MiB**
  - `run_containerd` 都约为 **2404 MiB**

## 最终结论

- 如果关心 **系统总内存变化**，应以 `MemAvailable` 为主：
  - **view 更优**
  - 在 `settle_60s` 稳定点，`view` 比 `no-view` 少损失约 **1790.0 MiB** 可用内存
- 如果关心 **共享内存占用**，结论更明显：
  - **view 明显更优**
  - `no-view` 额外多出约 **1.4 GiB Shmem**
- 如果关心 **存储占用**：
  - 两者在稳定点几乎无差别
  - 差异主要不在 devmapper thin-pool 或 `run_containerd` 上
